# Медиа на мобильных: ускорение загрузки

Дата: 2026-07-16
Статус: дизайн согласован, план не написан

## Задача

На мобильных сайт открывается медленно, медиа из MinIO ползёт. Причина найдена
замером, а не догадкой: видео портфолио весят 12–22 МБ каждое, и делает их
такими наш собственный код.

## Что показал замер (прод, 15 видео в бакете `portfolio`)

| | видео 1 | видео 2 |
|---|---|---|
| разрешение | 1080×1920 | 1080×1920 |
| битрейт | 4.7 Мбит/с | **7.2 Мбит/с** |
| вес | 13 МБ | 23.6 МБ |
| профиль | Constrained Baseline | Constrained Baseline |

7.2 Мбит/с выше типичного мобильного канала: видео физически не успевает
грузиться быстрее, чем играет.

Показываются они в карточке `.portfolio_card { max-width: 320px; aspect-ratio: 2/3 }`
— то есть максимум 320 CSS-пикселей. Полноэкранного просмотра нет, `controls`
нет, все теги `muted` + `aria-hidden`: это декоративные петли.

## Корень: `api/helpers/FfmpegHelper.php:21`

```
ffmpeg -i IN -vcodec libx264 -profile:v baseline -level 3.1 -pix_fmt yuv420p \
       -acodec aac -movflags +faststart -y OUT
```

Три беды в одной строке:

1. **Нет `-vf scale`** — разрешение остаётся исходным. Админ снимает вертикальное
   1080p на телефон, оно таким и уезжает в бакет.
2. **`baseline`** отключает CABAC и B-кадры — жмёт заметно хуже. Профиль для
   телефонов десятилетней давности.
3. **Нет потолка битрейта.** CRF по умолчанию держит качество, а не вес: детализированный
   исходник даёт 7 Мбит/с.

Плюс `-acodec aac` тащит звук в видео, размеченные `muted` — его никто не услышит.

## Решения и обоснование

| Решение | Выбрано | Почему не альтернатива |
|---|---|---|
| Целевое разрешение | 720×1280 (короткая сторона ≤720) | 1080p стоит +60% веса ровно там, где болит. Задача — «медленно на мобилах», а не «недостаточно резко» |
| Существующие файлы | Перекодировать на месте, оригинал в бакет-бэкап | Без бэкапа необратимо: исходников загрузки не существует. Новые ключи + правка БД решают проблему протухшего кеша, которой сейчас нет |
| Cache-Control | 30 дней | Ровно то, что проект уже выбрал во `frontend.conf`. Год + `immutable` не прощает перекодировку на месте |
| Мины autoplay | Скопировать существующий паттерн | Общий `useLazyVideo()` не ускоряет ни на байт, но рискует регрессией в двух самых посещаемых вью |
| `preset` | не задавать (medium) | Замер: medium 5 с / 4684 КБ, slow 6 с / 4620 КБ. 1.4% веса за +20% времени |

## Замеры, на которых стоит дизайн

Одно и то же видео (оригинал 23 МБ, 1080×1920, 7.2 Мбит/с):

```
как сейчас (baseline, без scale)        → 19 МБ          (почти не помогает)
1080×1920 high CRF26 ≤3Мбит/с -an       → 7.4 МБ  2.4 Мбит/с
720×1280  high CRF26 ≤2Мбит/с -an       → 4.6 МБ  1.5 Мбит/с   ← выбрано
```

15 видео: было ~230 МБ, станет ~45 МБ.

Выражение `scale` проверено на всех трёх случаях:

```
1080×1920 → 720×1280     уменьшение
1920×1080 → 720×406      уменьшение, не апскейл
480×854   → 480×854      апскейл запрещён (min)
```

## 1. Кодирование новых загрузок

`api/helpers/FfmpegHelper.php`:

```
ffmpeg -i IN -vf "scale='min(720,iw)':-2" -c:v libx264 -profile:v high -crf 26 \
       -maxrate 2M -bufsize 4M -pix_fmt yuv420p -an -movflags +faststart -y OUT
```

- `scale='min(720,iw)':-2` — короткая сторона ≤720, `min` запрещает апскейл,
  `-2` держит высоту чётной (требование `yuv420p`).
- `baseline` → `high` — возвращает CABAC и B-кадры.
- `-crf 26` + `-maxrate 2M -bufsize 4M` — capped CRF: качество с потолком веса.
- `-an` — звука нет ни в одном потребителе.
- `-level 3.1` убран: x264 подберёт сам.
- `-preset` не задаём — дефолт medium, замер выше.

**`-an` касается трёх точек сразу.** Хелпер общий: портфолио
(`AdminPortfolioController:81`), медиа категорий (`AdminServicesController:147`),
видео «о нас» (`AdminSystemController:276`). Все три тега `muted`. Если
понадобится звук — `-an` снимать осознанно.

## 2. Перекодировка 15 существующих

Разовый скрипт в `scripts/` (не рантайм). На каждый объект бакета `portfolio`:

1. `ffprobe` → **пропустить, если ширина ≤720 и битрейт ≤2.2 Мбит/с**;
2. оригинал скопировать в бакет `portfolio-originals` (создать, приватный);
3. перекодировать параметрами из §1;
4. залить на **тот же ключ**.

**Идемпотентность обязательна.** Без пропуска второй прогон пережмёт уже
пережатое и посадит качество ни за что. Проверяется прогоном дважды: второй
раз обязан пропустить всё.

**Тот же ключ, а не новый** — `video_url` в БД остаётся валидным, миграции нет,
осиротевших объектов нет.

**Порядок с §3 критичен: сначала перекодировка, потом `Cache-Control`.** Наоборот —
жирный файл залипнет у вернувшихся клиентов на месяц.

## 3. Cache-Control на медиа

Сейчас на объектах MinIO нет `Cache-Control` вообще — только `ETag` и
`Last-Modified`, поэтому браузер кеширует эвристически и передёргивает файлы.

`docs/nginx-host.conf` — эталонная копия, правка на сервере руками:

```nginx
location /portfolio/ {
    proxy_pass         http://127.0.0.1:9000;
    proxy_set_header   Host $host;
    proxy_set_header   X-Real-IP $remote_addr;
    proxy_set_header   X-Forwarded-Proto https;
    proxy_buffering    off;

    expires 30d;
    add_header Cache-Control "public";
    # add_header в location гасит родительские — nosniff проставляем заново,
    # иначе он пропадёт именно с пользовательского контента.
    add_header X-Content-Type-Options "nosniff" always;
}
```

**Только `/portfolio/`.** Медиа-домен отдаёт оба бакета, и `/order-photos/` —
приватные фото заказов по подписанным ссылкам. `Cache-Control: public` на них —
дыра: общий прокси сможет держать чужие фото.

## 4. Мины с autoplay

`autoplay` заставляет браузер скачать файл целиком и молча игнорирует
`preload="none"`. В проекте это уже задокументировано — `AboutView.vue:51`:
«страница тянула ~35 МБ на телефоне». В `AboutView` починили, в двух местах нет.

- **`HomeView.vue:530`** — `autoplay` вместе с `preload="none"`. Убрать `autoplay`,
  подключить к `IntersectionObserver`, который в этом файле уже есть. Стреляет
  сегодня: туда подставляется дефолт из бандла (2.4 МБ).
- **`ServiceCard.vue:65`** — `autoplay` вообще без `preload` и без ленивой загрузки.
  Добавить `preload="none"` + observer по образцу соседей. Сейчас не стреляет: ни у
  одной из 13 категорий на проде нет медиа. Латентная мина — заряжается в тот
  день, когда админ зальёт первое видео в категорию.

Четвёртая копия паттерна — осознанно. `PortfolioView` и `HomeView` уже почти
дословные копии друг друга; общий `useLazyVideo()` напрашивается, но не ускоряет
ни на байт и рискует регрессией там, где сейчас работает. Отдельным PR.

## 5. Тесты

**Что реально может сломаться:** параметры ffmpeg (кто-нибудь «упростит» строку
обратно) и идемпотентность скрипта.

`tests/api.test.js`:
- залить через `POST /admin/portfolio/upload` фикстуру 1080×1920 → `ffprobe`
  сохранённого объекта: ширина ≤720 и **звуковой дорожки нет**.

Фикстура (~30 КБ, сгенерирована `lavfi`) — в `tests/fixtures/`. `ffprobe`
дёргается через `docker compose exec` из теста: стенд тестам и так нужен.

Скрипт миграции: прогнать на дев-стенде дважды, второй прогон обязан пропустить
всё. Проверяется руками — разовый скрипт автотестом не покрываем.

Каждый тест проверяется откатом фикса: тест без обратной проверки не считается.
Между правкой PHP и прогоном ждать >2 секунд (`opcache.revalidate_freq=2`).

## Что осознанно не делаем

- **Общий `useLazyVideo()`** — отдельным PR, ревью там должно смотреть на
  регрессию поведения, а не на вес видео.
- **Постеры к видео, вторая рендиция под DPR 3, WebM/AV1** — YAGNI. Карточка
  320 px, клип декоративный.
- **`fastcgi_read_timeout`.** В `default.conf` не задан → дефолт 60 с, а PHP
  разрешает 120 (`docker/php/php.ini:4`). Длинная загрузка может упереться в
  nginx раньше, чем в PHP. Проблема существует и сейчас; наша правка её не
  усугубляет — кодирование не стало дольше (26-секундный ролик: 5 с). Отмечаем,
  не чиним.
- **Перевод бакета `portfolio` на CDN** — инфраструктура, вне задачи.
